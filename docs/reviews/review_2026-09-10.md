## Critical Findings

### C-1: STA Thread Message Pump Starvation & Hang on Exit

- **File:** `native/src/MindFlow.Win32/Hooks/WinEventTracker.cs` — Lines 119–145
- **Severity:** CRITICAL
- **Component:** Native C# / Win32 Subsystem

**Issue:** The `GetMessage` loop blocks the STA thread indefinitely. `Dispose()` cancels a
`CancellationToken`, but `GetMessage` won't evaluate it until a new Win32 message arrives — causing the
tracker to **hang on application exit**. Additionally, `ActiveWindowChanged` fires synchronously on the
STA thread; any slow subscriber (UI updates, DB queries) will starve the message pump and drop system events.

**Recommendation:**
1. Call `PostThreadMessage(threadId, WM_QUIT, 0, 0)` in `Dispose()` to break the `GetMessage` loop cleanly.
2. Dispatch `ActiveWindowChanged` to `Task.Run()` to keep the STA thread lightweight.

## High Severity Findings

### H-1: Missing Negative Cache for Expensive Audio Checks

- **File:** `backend/tracker.py` — Lines 712–747
- **Component:** Python Backend / Tracker

**Issue:** The fast-path cooldown lock (`_last_audio_active_time`) only prevents re-evaluation if audio
*was recently active*. When audio is **not** playing, the function falls through and executes expensive
`check_windows_audio_active()` COM calls on *every single invocation*. Since `is_passive_viewing_active`
polls this frequently, it causes severe CPU spikes when audio is off.

**Recommendation:** Track `_last_audio_check_time` and throttle all OS-level audio checks to max once
every 5 seconds, regardless of positive/negative result.

---

### H-2: DuckDB Thread Safety — Shared Connection Without Synchronization

- **File:** `backend/columnar_analytics.py` — Lines 251, 384, 447
- **Component:** Python Backend / Analytics

**Issue:** `_get_connection()` returns a shared `_duck_conn` instance. The background `_batch_worker`
executes batch inserts holding `_write_lock`, but analytical queries retrieve the connection using the
reentrant `_lock` and execute without holding `_write_lock`. Concurrent read/write on the same raw
DuckDB connection can cause crashes.

**Recommendation:** Return thread-local cursors (`conn.cursor()`) for queries, or synchronize analytical
reads with `_write_lock`.

---

### H-3: Battery Scale Normalization Logic Bug

- **File:** `backend/companion_service.py` — Lines 27–28
- **Component:** Python Backend / Companion AI

**Issue:** `if current_energy <= 5.0: current_energy = current_energy * 20.0` — intended to convert
legacy 1–5 scale to 0–100. But if a user's actual 0–100 battery drops to a critically low value
(e.g., 4%), this heuristic multiplies it to 80%, **completely masking exhaustion alerts**.

**Recommendation:** Remove the value-based heuristic. Use a strict 0–100 scale across the application,
or pass an explicit `is_legacy_scale` flag.

---

### H-4: UI Thread Blocking in Workspace Sweep

- **File:** `backend/workspace_manager.py` — Lines 398–415
- **Component:** Python Backend / Workspace Manager

**Issue:** `sweep_back_all_async()` accepts `timeout=5.0` and calls `thread.join(timeout=timeout)`. If
invoked from the main UI thread, it blocks the event loop for up to 5 seconds.

**Recommendation:** Remove `thread.join()` to make it truly fire-and-forget, or use an async
callback/event notification.

---

### H-5: Native ModeEngine — Idle Detection Preempts Manual Override

- **File:** `native/src/MindFlow.Core/State/ModeEngine.cs` — Lines 74–94
- **Component:** Native C# / State Machine

**Issue:** `EvaluateTick` checks idle timeout *before* checking the `ManualOverrideUntil` guard. If
`idleSeconds >= IdleTimeoutSeconds`, it transitions to `Rest` regardless of manual locks — breaking
the user's manual timer focus.

**Recommendation:** Move the Manual Override Guard (Step 2) above the Idle Detection Trigger (Step 1)
to properly enforce user intent and 120s cooldown hysteresis.

---

### H-6: Native SQLite — Long-Lived Writer Connection Blocks Checkpointing

- **File:** `native/src/MindFlow.Data/Database/MindFlowDb.cs` — Lines 173–208
- **Component:** Native C# / Database

**Issue:** `ProcessWriteQueueAsync` opens a connection and holds it indefinitely while polling
`_writeChannel`. This long-lived writer connection prevents WAL checkpointing.

**Recommendation:** Scope the `SqliteConnection` to batches. Read from channel → open connection →
execute batch in transaction → dispose immediately.

---

### H-7: Native TaskClassifier — O(N) Substring Search on Hot Path

- **File:** `native/src/MindFlow.Core/Classification/TaskClassifier.cs` — Lines 108–126
- **Component:** Native C# / Classification

**Issue:** Uses `.Any(k => cleanProcess.Contains(k))` iterating over keyword lists for every
classification attempt. Violates the <1ms tracking loop requirement and causes excessive allocations.

**Recommendation:** Compile `_workKeywords` and `_rechargeKeywords` into unified
`Regex(@"\b(code|visual studio|...)\b", RegexOptions.Compiled)` patterns.

---

### H-8: App.py — Monolithic Architecture (~1200 Lines)

- **File:** `app.py`
- **Component:** Python / App Entry Point

**Issue:** Single file handles process lifecycle, GUI launching, state machine orchestration, regex
caching, activity classification, and `CognitiveBattery` math — violating separation of concerns.

**Recommendation:** Extract `CognitiveBattery` → `battery.py`, classification/regex → `classifier.py`.
Keep `app.py` for initialization, process management, and the core event loop only.

---

### H-9: App.py — DB Connection Lifecycle Anti-Pattern

- **File:** `app.py` — Line ~1002
- **Component:** Python / App Entry Point

**Issue:** `db.close_thread_connection()` is manually called at the end of each tick in the
`while True:` loop. If an exception occurs earlier in the tick, the connection leaks. This anti-pattern
relies on the caller to manage connection lifecycles.

**Recommendation:** Refactor `db` wrapper methods to use internal context managers
(`with sqlite3.connect(...) as conn:`) for automatic cleanup.

## Medium Severity Findings

### M-1: Worker Thread Connection Thrashing

- **File:** `backend/database.py` — Lines 391–393
- **Issue:** DB worker thread calls `close_thread_connection()` after every single task. Forces re-open
  overhead at high frequencies, negating WAL mode advantages.
- **Fix:** Keep worker connection open during normal operation. Only close on transient errors or
  shutdown sentinel.

### M-2: Inappropriate Queuing for In-Memory Buffer Updates

- **File:** `backend/database.py` — Line 1338
- **Issue:** `log_app_usage` is decorated with `@queued_write` (wait=True), but only updates an
  in-memory dictionary. Unnecessary thread context switch violates <1ms requirement.
- **Fix:** Remove `@queued_write` decorator — let it execute synchronously since it only performs
  fast dict mutations.

### M-3: CRDT Tombstone Accumulation / Memory Leak

- **File:** `backend/crdt_sync.py` — Lines 668–673
- **Issue:** `garbage_collect_tombstones()` is implemented but never scheduled. Long-running instances
  infinitely accumulate deleted elements.
- **Fix:** Integrate periodic GC trigger during merge operations or schedule a recurring background task.

### M-4: Task Classifier Background Queue Flooding

- **File:** `backend/task_classifier.py` — Lines 324–332
- **Issue:** Persistent ambiguous titles push thousands of identical tuples into `_bg_queue`
  (maxsize=1000), crowding out distinct titles.
- **Fix:** Add a `_pending_enrichment` set to deduplicate before enqueueing.

### M-5: Native Timestamp Format Schema Drift

- **File:** `native/src/MindFlow.Data/Database/MindFlowDb.cs` — Lines 267, 358, 425
- **Issue:** C# saves timestamps as `"yyyy-MM-dd HH:mm:ss"`. Python uses ISO 8601 with `T` separator
  and microseconds. Fatal parity error for cross-stack data sharing.
- **Fix:** Use `.ToString("o")` (ISO 8601 round-trip format).

### M-6: Native HotkeyManager Thread Safety

- **File:** `native/src/MindFlow.Win32/Hotkeys/HotkeyManager.cs` — Line 36
- **Issue:** `_registeredActions` uses standard `Dictionary`. Concurrent register/unregister can
  corrupt data.
- **Fix:** Use `ConcurrentDictionary<int, Action>`.

### M-7: App.py Settings Polling Every 5 Seconds

- **File:** `app.py` — Lines 754–768
- **Issue:** State machine queries `db.get_settings()` and `db.get_adaptive_times()` every 5 seconds.
  Creates unnecessary DB locks.
- **Fix:** Event-based invalidation (similar to `register_cache_invalidation_listener`).

### M-8: App.py Dead Code — Unused Constants

- **File:** `app.py` — Lines 83–99
- **Issue:** `PHYSICAL_STRETCHES` and `EYE_EXERCISES` lists are defined but never referenced.
- **Fix:** Move to `nudge_engine` or remove.

### M-9: Native Win32 Test Mocking Bypasses Real Behavior

- **File:** `native/tests/MindFlow.Tests/HotkeyTests.cs`
- **Issue:** Tests pass `IntPtr.Zero` or fake handles, testing only graceful failure paths. Zero
  confidence in actual Win32 interop.
- **Fix:** Spin up a hidden message-loop window in test fixtures for real hook registration.
